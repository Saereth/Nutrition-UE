# 4.17.0

## Fixed
- Restored `INutrientManager.add(List<Nutrient>, float)` to match the upstream WesCook API. The previous UEL releases only exposed `add(Map<Nutrient, Float>)`, which caused `NoSuchMethodError` at runtime for dependents compiled against upstream — notably Magiculture Integrations' `AutoFeederDevice`, which crashed worlds in FTB Interactions Remastered whenever a mob applied a potion effect ([FTB-Modpack-Issues #11896](https://github.com/FTBTeam/FTB-Modpack-Issues/issues/11896)). Both overloads now coexist, so this is a drop-in fix with no behavior change for existing UEL users.

## Internal
- Refactored the mod's package group from `ca.wescook.nutrition` to `com.breakinblocks.nutrition`. No behavior change; mod id, config paths, and save data are untouched.
