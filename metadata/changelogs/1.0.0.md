# 1.0.0

First release of Nutrition-UE, forked from Nutrition-UEL 4.16.0.

## Fixed
- Restored `INutrientManager.add(List<Nutrient>, float)` to match the upstream WesCook API. UEL 4.16.0 only exposed `add(Map<Nutrient, Float>)`, which caused `NoSuchMethodError` at runtime for dependents compiled against upstream — notably Magiculture Integrations' `AutoFeederDevice`, which crashed worlds in FTB Interactions Remastered whenever a mob applied a potion effect ([FTB-Modpack-Issues #11896](https://github.com/FTBTeam/FTB-Modpack-Issues/issues/11896)). Both overloads now coexist, so dependents compiled against either API work drop-in.

## Build
- Ported the Gradle toolchain to the latest [GregTechCEu/Buildscripts](https://github.com/GregTechCEu/Buildscripts) (RFG 1.4.x, properties split into `gradle.properties` + `buildscript.properties`, Gradle 8.9). The old GTNH maven (`jenkins.usrv.eu:8081`) is offline; the new toolchain uses `nexus.gtnewhorizons.com`.
- Runtime Java package kept at `ca.wescook.nutrition` for drop-in compatibility with every mod that references Nutrition classes by fully-qualified name.
