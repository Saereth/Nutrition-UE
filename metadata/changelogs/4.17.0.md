# 4.17.0

> **Superseded by 4.17.1** — the package rename below broke binary compatibility for dependents. Use 4.17.1 instead.

## Fixed
- Restored `INutrientManager.add(List<Nutrient>, float)` to match the upstream WesCook API. The previous UEL releases only exposed `add(Map<Nutrient, Float>)`, which caused `NoSuchMethodError` at runtime for dependents compiled against upstream — notably Magiculture Integrations' `AutoFeederDevice`, which crashed worlds in FTB Interactions Remastered whenever a mob applied a potion effect ([FTB-Modpack-Issues #11896](https://github.com/FTBTeam/FTB-Modpack-Issues/issues/11896)). Both overloads now coexist.

## Internal (reverted in 4.17.1)
- Refactored the runtime Java package from `ca.wescook.nutrition` to `com.breakinblocks.nutrition`. This broke `NoClassDefFoundError: ca/wescook/nutrition/nutrients/NutrientList` for every dependent that referenced Nutrition classes by name (Magiculture Integrations, JustEnoughMagiculture, and likely others). Reverted in the next release.

## Build
- Ported the Gradle toolchain to the latest [GregTechCEu/Buildscripts](https://github.com/GregTechCEu/Buildscripts) (RFG 1.4.x, properties split into `gradle.properties` + `buildscript.properties`, Gradle 8.9). The old GTNH maven (`jenkins.usrv.eu:8081`) is offline; the new toolchain uses `nexus.gtnewhorizons.com`.
